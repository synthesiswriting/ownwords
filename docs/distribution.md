# Distribution maintenance

Build from a clean Ownwords checkout whose HEAD equals its exact package-version tag. The builder materializes that committed Git tree before copying package files; ignored local logs, caches and build debris cannot enter a release. Distribution metadata records the Ownwords commit and tag alongside the core identity. The release builder requires a previously published, verified Synthesis core thin archive and its SHA-256. It never downloads mutable core code or embeds the optional skill catalog in the package. The builder extracts only regular bounded members, verifies the bootstrap hash and release identity, and records every vendor file's hash and mode. Ownwords setup and the explicit `ownwords synthesis <activate|deactivate|status|doctor|repair|update> [args]` bridge verify this inventory before executing the launcher. The bridge preserves arguments and child failures or termination signals, forwards incoming cancellation to its isolated child process group, and waits for termination; ordinary authoring commands never invoke it. `ownwords synthesis activate --profile full` (or `--profile skills-only`) activates verified staged assets without installing a second package.

`python3 -B scripts/build-distribution.py --output /absolute/new/output --core-archive /absolute/core.tar.gz --core-sha256 HASH` generates the complete npm/Bun package archive, direct archive, Homebrew formula, checksum-bound `install.sh`, `SHA256SUMS` and `distribution.json`. The checksum list covers both archive and installer. An optional `--npm-cache PATH` uses a previously populated npm cache in offline mode. Without it, the build acquires only lockfile-pinned production dependencies through npm with scripts disabled. Package manager installation and ordinary Ownwords invocation never install Synthesis. The explicit shell installer verifies the archive, stages a version directory, atomically records launcher ownership and then runs `ownwords setup`; download and setup children receive incoming cancellation, are reaped before exit, and preserve their exit codes or signals; `--no-dormant-core` declines optional acquisition. It requires Node 18+, Python 3.9+ and curl, with Git and Python 3.12–3.14 required only for default core staging.

The output archive is deterministic: normalized file order, ownership, modes and timestamps produce identical SHA-256 for identical source, vendor archive and dependency lockfile. It bundles production dependencies so direct users and temporary npm/Bun consumers can run the same JavaScript files. The npm package name stays `ownwords`; Bun consumes that same registry package. Published dependency ranges are narrowed to the exact lockfile versions. Bun may still resolve these packages through npm metadata during installation; only direct extraction and the verified npm offline consumer establish an offline installation path. Homebrew installs the generated archive under its own prefix and declares Node. Optional setup prerequisites are documented separately to avoid adding Python or Git to ordinary CLI requirements.

Run the existing `npm test` and `npm run lint`, then `scripts/test-distribution.py` with the same core archive/hash, a populated npm cache and a new output directory. Its temporary tagged source fixture builds twice and compares checksums, installs actual npm and Bun consumers, extracts a direct consumer, and runs the real curl installer twice with local transport for that same archive, verifies inert opt-out, lifecycle bridge help, honest absent-core status, packaged documentation and unchanged homes, and runs existing local HTML conversion. It never calls WordPress, an LLM or a native agent service. Fixture source identities are labeled and do not constitute a public release.

The manually dispatched Verified distribution workflow binds a specific Ownwords tag and exact core archive URL/hash, runs checks and preserves artifacts. Publication is an explicit boolean input that defaults to false. The release job installs and verifies npm 11.15.0 and checks Node is at least 22.14.0, satisfying npm trusted publishing requirements. The npm package must authorize `distribution.yml` as its trusted GitHub workflow. These release-toolchain requirements do not change the ordinary CLI's Node 18 minimum. Publish the generated tarball, not a raw source directory. Upload the archive/checksums/metadata to the matching GitHub release, then publish the generated Homebrew formula in the Synthesis tap. AUR publication is deferred and is not advertised as an available command.

Source checks and temporary consumers do not prove registry publication. After publishing, verify npm/Bun installation from the registry, the ordinary GitHub asset URL, Homebrew through the published tap, and the versioned shell installer over ordinary HTTPS.
