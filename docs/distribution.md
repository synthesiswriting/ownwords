# Distribution maintenance

Build from a clean Ownwords checkout whose HEAD equals its exact package-version tag. The builder materializes that committed Git tree before copying package files; ignored local logs, caches and build debris cannot enter a release. Distribution metadata records the Ownwords commit and tag. Every channel ships Ownwords alone: the package holds the CLI, library, type definitions, documentation and locked production dependencies, and no other software. Ownwords does not install or manage the synthesis work system, which installs separately from the [downloads page](https://synthesiswork.org/download/).

`python3 -B scripts/build-distribution.py --output /absolute/new/output` generates the complete npm/Bun package archive, direct archive, Homebrew formula, checksum-bound `install.sh`, `SHA256SUMS` and `distribution.json`. The checksum list covers both archive and installer. An optional `--npm-cache PATH` uses a previously populated npm cache in offline mode. Without it, the build acquires only lockfile-pinned production dependencies through npm with scripts disabled. The shell installer verifies the archive, stages a version directory and atomically records launcher ownership; it runs nothing it installed. Its child processes receive incoming cancellation, are reaped before exit, and preserve their exit codes or signals. The installer requires Python 3.9+ and curl, and Ownwords requires Node 18+.

The output archive is deterministic: normalized file order, ownership, modes and timestamps produce identical SHA-256 for identical source and dependency lockfile. It bundles production dependencies so direct users and temporary npm/Bun consumers can run the same JavaScript files. The npm package name stays `ownwords`; Bun consumes that same registry package. Published dependency ranges are narrowed to the exact lockfile versions. Bun may still resolve these packages through npm metadata during installation; only direct extraction and the verified npm offline consumer establish an offline installation path. Homebrew installs the generated archive under its own prefix and declares only Node; the launcher resolves other commands, such as `curl`, through the runtime `PATH`.

Run the existing `npm test` and `npm run lint`, then `python3 -B scripts/test-distribution.py --npm-cache PATH --output /absolute/new/output` with a populated npm cache (`npm ci --cache PATH` in the checkout fills one). Its temporary tagged source fixture builds twice and compares checksums, installs actual npm and Bun consumers, extracts a direct consumer, and runs the real curl installer twice with local transport for that same archive. It checks that the archive and installed packages contain no vendor tree or setup module, that the built installer has no setup step, that no channel dispatches a `setup` or `synthesis` command, that packaged documentation is present, that local HTML conversion works, and that installation and conversion leave the isolated homes unchanged. It never calls WordPress or an LLM. Fixture source identities are labeled and do not constitute a public release.

The manually dispatched Verified distribution workflow binds a specific Ownwords tag, runs checks and preserves artifacts. Publication is an explicit boolean input that defaults to false. The release job installs and verifies npm 11.15.0 and checks Node is at least 22.14.0, satisfying npm trusted publishing requirements. The npm package must authorize `distribution.yml` as its trusted GitHub workflow. These release-toolchain requirements do not change the ordinary CLI's Node 18 minimum. Publish the generated tarball, not a raw source directory. Upload the archive/checksums/metadata to the matching GitHub release, then publish the generated Homebrew formula in the `synthesisengineering/tap` tap. No AUR package is published or advertised.

Source checks and temporary consumers do not prove registry publication. After publishing, verify npm/Bun installation from the registry, the ordinary GitHub asset URL, Homebrew through the published tap, and both the versioned shell installer and the README's `releases/latest/download/install.sh` URL over ordinary HTTPS. Preserve separate results for source, artifact, published channel and runtime behavior.
